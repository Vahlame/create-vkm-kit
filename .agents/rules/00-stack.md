## Stack (repo)

- **Languages:** Markdown (vault + docs), TypeScript (tooling), Go 1.25+ (`obsidian-memoryd`), Python 3.11+ (optional RAG).
- **Runtimes:** Node 20+, Bun or `npx tsx` for maintainer scripts; `uv` for `basic-memory`.
- **Primary MCP:** `uvx basic-memory mcp` with `BASIC_MEMORY_HOME=<vault>` (**stdio** in `mcp.json`; recommended default).
- **Optional transport:** Streamable HTTP URL for `basic-memory` (e.g. `http://127.0.0.1:8765/mcp`) requires a **separate always-on listener** you run (terminal or Task Scheduler action you define; see `docs/en/sync.md`); see `config/mcp/basic-memory-streamable-http.json`. Default port **8765** avoids collisions with common dev servers on **8000** / **8080** / **3000** (see ADR-0016).
- **Hybrid MCP (recommended vault surface):** `node packages/obsidian-memory-mcp/src/hybrid-mcp.mjs` — twenty-five tools: `vault_hybrid_search` (BM25 + semantic via RRF; returns the matching **section** — passage-first; all-opt-in/default-off knobs: `graph: true` fuses `[[wikilink]]`-adjacent notes — ADR-0019, `graphTyped: true` verb-weights typed relations — ADR-0027, `recency: true` favors recently-modified notes — ADR-0021, `importance: true` favors hub notes by in-degree — ADR-0027, `mmr: true` diversifies near-duplicates — ADR-0028, `passageWindow: N` widens the returned passage, `rerank: true` adds a cross-encoder precision pass — ADR-0026, needs the `[rerank]` extra; compact wire format by default, `explain: true` restores ranking diagnostics and default `limit` is 10 — ADR-0034; CLI/env levers `--pin-failures` / `--usage` boost recorded `[failure]`/`[gotcha]` lessons and demonstrably-used notes — ADR-0038), `vault_fts_search` / `vault_fts_index`, `vault_complete` (prefix autocomplete over titles / filenames / `#tags`), the structured knowledge graph `vault_relations` / `vault_observations` / `vault_kg_suggest` (typed relations + categorized observations — ADR-0023), `vault_memory_report` (indices + hygiene/compaction candidates + `cold_notes`, `reflect: true` adds consolidation proposals, read-only — ADR-0024/0038), vault-locked `vault_read_file` (returns a content `etag`) / `vault_write_file` / `vault_edit_file` (opt-in `ifMatch` precondition + advisory write lock — ADR-0037; every write/edit/append also runs a **write-time hygiene lint** — non-canonical observation categories, unresolved `[[wikilinks]]`, orphan-at-birth notes — warning-only, scoped to the text being written) / `vault_delete_file` (soft delete to `.trash/` by default; `permanent: true` unlinks; refuses core protocol notes; reports notes still `[[linking]]`) / `vault_move_file` (rename/move; refuses overwrite without `overwrite: true`; reports stale `[[wikilink]]` refs; restore-from-trash is a move back) / `vault_append_file` (CRLF-aware append — the SESSION_LOG one-liner path, no anchor round-trip) / `vault_frontmatter_set` (top-level scalar YAML keys without text-matching — `status`/`last_verified` promotions) / `vault_backlinks` (who `[[links]]` here, read-only, pre-delete/move impact check) / `vault_git_history` (commits + old versions of a note via the sync repo, read-only — recovery even after `permanent: true`) / `vault_list_directory`, `vault_rotate_log` (archive old `SESSION_LOG` entries — `##` sections or top-level bullets — keeping the newest N; bridges Python `json-rotate-log`), `vault_audit` (vault health: bloat, broken links, sync conflicts, git state, opt-in `memory-schema.json` checks), `memory_extract_candidates`, `assemble_context` (one budgeted call: decisions + stack + passages for a project), and — only when the Postgres projection is enabled (`VKM_PG=1`, ADR-0084) — `vault_pg_status` (projection health: backend, row counts, last sync; starts the local pg-service when needed), `vault_graph_hops` (multi-hop typed relation traversal via recursive SQL) and `vault_timeline` (recent memory activity from the projection's sync log). Bridges Python `obsidian-memory-rag` (optional `[vec]` extra + `OBSIDIAN_MEMORY_SQLITE_VEC=1` accelerates the cosine scan in-file via sqlite-vec, ranking-identical — ADR-0025); see `config/mcp/obsidian-memory-hybrid.json`. Wire it in Claude Code with `create-vkm-kit --ide claude` (runs `claude mcp add`) or Codex CLI with `--ide codex` (runs `codex mcp add`); `create-vkm-kit --full` wires Codex + Claude with hybrid+semantic+index+rules in one shot (ADR-0022).
- **Postgres projection (optional, ADR-0084):** `packages/vkm-memory-pg` — a **derived, disposable** copy of the `fts.sqlite` index in Postgres, for multi-hop typed traversal (recursive CTEs), SQL analytics, a temporal activity log and `LISTEN`/`NOTIFY` real-time push. Embedded **PGlite 0.5.4** (Postgres 18 as WASM, in-process) by default, or an external server via `VKM_PG_DSN`; vectors are text literals `'[…]'::vector` because the `pgvector` npm package needs Node 22. One single-writer `pg-service` on `127.0.0.1` (token in `service.token`, `GET /api/health` exempt) fronts it; `vkm-pg-migrate` builds it, `--rebuild` recreates it, `--enrich` adds a local-Ollama pass that writes ONLY into `suggestions` — never notes, relations, observations or `.md`. Data lives OUTSIDE the vault in `~/.vkm/pg/<slug>/` so git-sync never churns. The CI-gated SQLite ranking path is untouched. Installer: `--postgres` (default on) / `--no-postgres` / `--pg-dsn <string>`.
- **Scoped memory (ADR-0086):** ONE vault, ONE index — namespaces instead of fragmentation: `PROJECTS/<name>.md` per project, top-level `AGENTS/<agent-name>.md` per agent (same frontmatter / typed relations / `[category]` observations; starter vault ships `AGENTS/README.md` + `AGENTS/TEMPLATE.md`); retrieval takes a generic `scope` filter (CLI `--scope`, MCP param `scope`, PG query param `scope`) — a posix-style relative path prefix matched at segment boundary (`P == S`, `P == S + ".md"`, or `P.startswith(S + "/")`), case-sensitive, applied AFTER `section`, rejecting with an error any scope containing `..`, a leading `/`, a drive letter or backslashes (e.g. `scope="AGENTS/vkm-implementer"` → one agent's memory; `assemble_context` takes `agentName`). No vault-per-agent — leakage is handled by scoping (ADR-0074).
- **Real-time console (optional, ADR-0085):** `cmd/vkm-console` — one Go binary serving a `go:embed`-ed page on `127.0.0.1:4930` with daemon health, memory stats + graph, token telemetry, Postgres projection state and research/download logs, refreshed over its own SSE stream (`--refresh`, default 5 s, plus debounced `fsnotify` pushes). **Strictly read-only** over every source (no lock, no writes, never opens `fts.sqlite` or a datadir, the projection only through its HTTP API, no subprocess except the browser), and it opens **no window** unless the user passes `--open` (ADR-0078). Flags: `--vault`, `--port` / `VKM_CONSOLE_PORT`, `--open`, `--refresh`. Installer: `--console`; build: `npm run build:console`.
- **Environment variables (Postgres + console):** `VKM_PG=1` enables the projection · `VKM_PG_DSN` fronts an external Postgres instead of PGlite · `VKM_PG_PORT` pins the service port (default: dynamic, recorded in `service.json`) · `VKM_PG_DATA_ROOT` overrides the per-vault home (default `<home>/.vkm/pg`) · `VKM_PG_MODEL` picks the Ollama model for `--enrich` (default `phi4-mini:3.8b-q4_K_M`) · `VKM_CONSOLE_PORT` moves the console off 4930. Vault resolution everywhere: `VKM_VAULT` → `BASIC_MEMORY_HOME` → `OBSIDIAN_MEMORY_VAULT`.
- **Bridge (legacy clients):** `mcp-remote` pinned **>= 0.1.16** (see `docs/security/mcp-remote-rce.md`).
